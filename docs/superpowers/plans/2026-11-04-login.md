# Login Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development with focused implementation and independent review.

**Goal:** Deliver the approved Vietnamese login UI at `/` with Google, Apple, Facebook and accessible email/password interactions.

**Architecture:** Server page renders the static brand panel and layout. A client form owns transient form state and honest unconfigured-service notices. No credentials are transmitted or persisted.

**Tech Stack:** Existing Next.js 16 App Router, React 19, TypeScript, CSS, inline SVG. No new dependencies.

## Task 1: Implement the approved screen

- [x] Create `src/app/components/login-form.tsx`: accessible social buttons, native email/password validation, password visibility toggle, remember checkbox, inline live notices for login/register/reset. Use `autoComplete="email"` and `autoComplete="current-password"`; social buttons must have `type="button"`. Native HTML validation avoids adding authentication or duplicate validation logic to a frontend demonstration.
- [x] Create `src/app/components/icons.tsx`: shared SVG brand, provider, eye, arrow and lock icons, hidden from accessibility when decorative.
- [x] Replace `src/app/page.tsx` with static two-column composition and decorative CSS illustration. Keep a single h1 in the form; decoration is aria-hidden.
- [x] Replace `src/app/globals.css` with ivory/sage/teal styling; form at most 400px, clear focus, 44px interactive targets, one column below 900px, no overflow at 320px, reduced-motion support.
- [x] Update `src/app/layout.tsx` metadata and `lang="vi"`; preserve the existing font system.

## Task 2: Review and verify

- [x] Independently review implementation against the approved design and for code quality; resolve substantive findings.
- [x] Run `npm run lint`, `npx tsc --noEmit`, and `npm run build`; all must exit zero.
- [x] Use local Chrome if available to inspect desktop and mobile screenshots, overflow, labels, password toggle, checkbox, constraint validation and provider/reset/register messages. No persistent automated test suite for this reversible frontend-only screen; verify the actual browser behavior.
- [x] Record results and leave all work reviewable in the user's current workspace. No publishing or OAuth integration is part of this change.
